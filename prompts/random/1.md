Let me search for the current best practice, since this is a known friction point with devenv:This is a known bug in devenv 1.6 where `allowUnfree` in devenv.yaml is being ignored. There are a few workarounds:

**Option 1: Use the newer `nixpkgs.config` syntax**

Recent devenv versions support a more explicit configuration path. In your `devenv.yaml`:

```yaml
nixpkgs:
  config:
    allowUnfree: true
```

**Option 2: Use `permittedUnfreePackages` for specific packages**

Instead of allowing all unfree packages, you can selectively permit specific unfree packages by name:

```yaml
nixpkgs:
  permittedUnfreePackages:
    - mongodb-ce
```

**Option 3: Environment variable workaround in `.envrc`**

A workaround is to add it directly to the direnv configuration file `.envrc`:

```bash
source_url "https://raw.githubusercontent.com/cachix/devenv/main/direnvrc" "sha256-..."

export NIXPKGS_ALLOW_UNFREE=1
use devenv
```

**Option 4: Upgrade devenv**

The issue tracker shows this was fixed in later versions. Try:

```bash
devenv update
# or reinstall devenv to get the latest version
```

Check your version with `devenv version` — if you're on 1.6.x, upgrading to 1.7+ or 1.8+ should resolve this.

The most reliable immediate fix is **Option 3** (the `.envrc` workaround), while **Option 2** (permittedUnfreePackages) is the cleanest if it works with your devenv version.
